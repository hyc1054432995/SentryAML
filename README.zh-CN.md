# SentryAML（中文简介）

[English README](README.md) · [设计决策与排查记录](docs/decisions.md)

**一个端到端的反洗钱告警流程：规则 → 机器学习打分 → 会调查、会引用法规的 LLM Agent → 有审计记录的人工复核 → 可疑交易报告（STR）草稿。**

> 作品集项目。数据是公开的**合成**数据集（IBM AMLworld HI-Small，508 万笔交易），法规是公开的新加坡 MAS、STRO 文件和 FATF 指引。不是生产系统，不含任何真实客户数据。

## 三个数字

| | 结果 | 在哪里测的 |
|---|---|---|
| 告警量 | 召回率与规则引擎相同时，告警从 **354,479** 条降到 **2,216** 条（减少 99.4%），精确率 0.15% → **24.4%** | 时间外测试集，84.5 万笔，只跑一次 |
| 带引用的法规回答 | **128/128** 条论断与原文逐字核对通过，引用准确率 **1.000**，误拒 0 | 留出的测试题，只跑一次 |
| 分诊 Agent | **60/60** 条结论通过程序核验（每个数字都追溯到工具结果的具体字段），每条约 1 美分、中位 33 秒 | 冻结的测试样本，只跑一次 |

## 流程

1. **规则和 LightGBM** 给每笔交易打分；高分告警直接交给人。
2. **分诊 Agent** 用 9 个时点正确的 SQL 工具调查中间档告警。它用的是最小权限的数据库角色，在数据库层面读不到标签；结论里的每个数字都由程序核对。
3. **复核员**在网页上认领案件，先看证据，再看 Agent 的结论。状态机、双人复核、只追加的审计记录、认领租约全部写在 PostgreSQL 触发器里，网页、接口、命令行、直接写 SQL，哪条路都绕不过。
4. **STR 草稿**：结构化部分由 SQL 组装；理由由模型起草，程序核验每个数字的出处。页面上逐句显示数字出处，并用确定性规则标出容易"说过头"的句子。
5. **问法规**：在案件页上直接提问，回答逐字引用 MAS Notice 626 和 FATF 原文。只供参考，不会写进 STR。
6. **另一位 MLRO** 批准指定版本的草稿。

## 怎样保证结果可信

- 每个比较都在运行前写好采用规则；测试集只跑一次，脚本拒绝重跑。
- 负面结果和不显著的结果照样报告：分诊 Agent 主要结果的区间含 0；Optuna、HyDE、固定两轮检索都没有收益。
- 样本内的结果标明是样本内的：解读提示的规则是看着评分过的句子写的，在那些句子上标得准，不代表规则有效。
- 设计决策记录（`docs/decisions.md`）里有一节"我判断错过的地方"。

## 局限

合成数据，没有姓名、证件号、地址，可用的交易只有大约十天；知识库只有新加坡和 FATF 的材料；测试样本小，区间宽；单机演示，没有任务队列。

运行方法、测试命令、目录结构见 [English README](README.md)。
